## Conventions

- JSON, `camelCase` fields, plural kebab-case paths.
- `GET` list, `POST` create (201), `GET /{id}`, `PATCH /{id}` partial update,
  `DELETE /{id}` (204). Actions are `POST /{id}/{verb}`.
- Ids are integers, except user ids (text, from the auth library).
- Timestamps are UTC ISO 8601.
- Secrets are never returned. Responses carry `hasApiKey: true` instead.

## Errors

RFC 9457 problem details, `Content-Type: application/problem+json`:

```json
{
  "type": "https://unseenarr.invalid/problems/validation",
  "title": "Validation failed",
  "status": 422,
  "code": "validation",
  "detail": "name must not be empty",
  "errors": [{ "field": "name", "message": "must not be empty" }]
}
```

`code` is a stable machine-readable string. The frontend switches on `code`.

| Status | When |
|---|---|
| 400 | Malformed request |
| 401 | No valid session or API key |
| 403 | Authenticated, permission missing. Body names the required permission. |
| 404 | Resource does not exist |
| 409 | Conflict, for example duplicate TMDB id |
| 422 | Validation failed |
| 502 | An external service failed (TMDB, indexer, download client) |

A user without `library:read` gets 403 on a movie, not 404. Open question:
hide existence with 404 once per-library scoping exists.

## Pagination

`?page=1&pageSize=50&sort=title&order=asc`. Response:

```json
{ "items": [], "page": 1, "pageSize": 50, "total": 0 }
```

Maximum `pageSize` is 500. The movie list may return everything when
`pageSize=0`. Open question: confirm, or always page.

## Permissions per route

Each route declares one access rule through `ApiRouter` (`require`,
`authenticated`, or `public`) and extracts `Require<P>`, `Caller`, or
`Public` as needed. That single declaration enforces access at runtime and
writes `x-permission` into OpenAPI (`"public"`, `"authenticated"`, or
`"<resource>:<action>"`):

```rust
#[utoipa::path(get, path = "/api/v1/movies")]
async fn list_movies(_: Require<LibraryRead>, ...) { ... }

ApiRouter::new().require(Permission::LibraryRead, routes!(list_movies))
```

- Missing or invalid credentials return `401` (`code: "unauthorized"`).
- Missing permission returns `403` (`code: "forbidden"`, with
  `requiredPermission` and `detail` naming the required permission).
- A route coverage test calls `api::routes().verify()` and fails when a route
  has no access rule or disagrees with OpenAPI `x-permission`.

## Collections

A collection is created once, when the first movie of a TMDB collection is
added, adopted or refreshed. The row stays when its last movie is deleted.
`GET /collections` lists the rows with the count of movies in the library.
`GET /collections/{id}` adds the movies in the library and the ones missing,
which come from TMDB.

`PATCH /collections/{id}` sets `monitored`, `rootFolderId`,
`qualityProfileId` and `minimumAvailability`. Setting `monitored` to `true`
needs a root folder and a quality profile, and adds every movie of the
collection that is not in the library and that TMDB marks released or
announced. The new movies are monitored and carry the collection's defaults.
TMDB is asked before anything is stored, so a TMDB failure leaves the
collection as it was; send the request again to retry. The scheduled check
for new movies of a monitored collection is M5.

## SSE

`GET /api/v1/events`, `text/event-stream`. Events are filtered by the
caller's permissions at send time.

| Event | Data | Permission |
|---|---|---|
| `download.progress` | id, progress, speed, eta, state | `queue:read` |
| `download.state` | id, old state, new state | `queue:read` |
| `movie.updated` | movie id | `library:read` |
| `task.status` | task name, status | `system:tasks` |
| `permissions.changed` | user id; the client reloads `/me` | the affected user only |

The stream has no replay buffer and ignores `Last-Event-ID`: a reconnect
starts with new events only, and clients resync by refetching. A
`keep-alive` comment every 15 seconds keeps an idle connection open through
a reverse proxy.

## Versioning

`/api/v1` changes only in backward-compatible ways after V1. Before V1,
breaking changes are allowed.
